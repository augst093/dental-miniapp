## 📌 1. Бизнес-контекст и целевая модель продукта

- **Продукт:** Готовая к коммерческой продаже B2B-система автоматизации стоматологической клиники в Ташкенте.
- **Модель монетизации:** $450 единоразовая настройка и внедрение + $50/месяц абонентская плата за сопровождение (напоминания, AI-ассистент, обновления).
- **Целевая аудитория:** Владельцы частных стоматологических центров, главные врачи и администраторы клиник Ташкента (высокочековые процедуры: брекеты Damon $600–$1,200, элайнеры Spark $2,000–$3,500, импланты Straumann $450–$900 за зуб, виниры E.max $250 за единицу).
- **Главные боли клиники, которые решает продукт:**
  1. **Потеря лидов в нерабочее время:** 40%+ пациентов пишут ночью и в выходные. AI-бот отвечает за 2-3 секунды 24/7 на RU и UZ, квалифицирует интерес и забирает контакт.
  2. **Высокая доля неявок (No-Show Rate 20–30%):** Пациенты забывают о визитах. Автоматические интерактивные напоминания за 24ч и за 2ч с кнопками подтверждения сокращают неявки на 35–45%.
  3. **Перегрузка администратора рутиной:** 3–5 часов в день уходит на обзвоны для подтверждения. Система экономит ~4 минуты на каждом визите и высвобождает время администратора на живое обслуживание в холле.
  4. **Накладки и двойные записи (овербукинг):** Защита на уровне слотов исключает одновременную запись двух пациентов к одному доктору.
- **Локализация и специфика:**
  - Часовой пояс: `Asia/Tashkent` (UTC+5). Все слоты, таймлайны и напоминания привязаны строго к UTC+5.
  - Валюта: UZS (сум), с возможностью отображения ориентировочного эквивалента в USD.
  - Формат телефонов: Узбекистан `+998 XX XXX XX XX`.
  - Языки: Русский (RU), Узбекский (UZ — латиница), Английский (EN).

## 📋 3. Хронология и детализация всех 9 реализованных фаз

Проект был трансформирован из сырого демонстрационного шаблона в коммерческий B2B-продукт по следующему детальному плану:

### Фаза 0: Полный технический аудит (`docs/AUDIT.md`)
- Проведен комплексный аудит исходного кода: выявлены риски овербукинга, плейсхолдеры, хардкод лицензии, уязвимости отсутствия HMAC-валидации и риски рассинхронизации часовых поясов.
- Зафиксированы архитектурные константы и план работ.

### Фаза 1: Модель данных, жизненный цикл и слот-движок
- **Prisma Schema (`prisma/schema.prisma`):**
  - Таблицы: `Clinic`, `Doctor`, `Service`, `Patient`, `Appointment`, `Reminder`, `AuditLog`, `Setting`.
- **Конечный автомат жизненного цикла (`src/lib/appointmentLifecycle.ts`):**
  - Статусы: `pending` (Ожидает подтверждения), `confirmed` (Подтверждён), `reschedule_requested` (Запрос переноса), `cancelled` (Отменён), `completed` (Завершён успешно), `no_show` (Пациент не явился).
  - Строгая таблица разрешенных переходов `ALLOWED_TRANSITIONS`: запрещен переход из терминальных статусов (`completed`, `cancelled`), запрещен переход напрямую `pending ➔ completed` без предварительного подтверждения.
  - Каждое изменение статуса фиксируется в журнале аудита с автором (`patient`, `admin`, `bot`, `cron`).
- **Слот-движок (`src/lib/slots.ts`):**
  - Рабочие часы клиники 09:00 – 19:00, шаг слота 30 минут.
  - Защита от бронирования «задним числом» и минимальный lead time: **2 часа** до начала слота.
  - Атомарная защита от овербукинга: если слот занят записью в статусе `pending` или `confirmed`, он блокируется. При отмене (`cancelled`) слот мгновенно освобождается.
- **Работа с таймзоной (`src/lib/timezone.ts`):**
  - Все даты конвертируются между `Asia/Tashkent` (UTC+5) и ISO UTC. Исключена путаница с летним временем и локальным временем устройства пациента.
- **Двухуровневый репозиторий (`src/lib/db.ts`):**
  - Подключение к PostgreSQL через Prisma ORM при наличии переменной `DATABASE_URL`.
  - Автономный in-memory репозиторий с предзаполненными реалистичными записями за последние 14 дней (подтвержденные визиты, отмены, неявки, спасенные слоты) для демонстрации собственнику клиники без необходимости поднимать внешнюю СУБД.
- **Набор автоматизированных тестов (`src/__tests__/test_lifecycle_and_rules.ts`):**
  - 17/17 тестов проверяют переходы стейт-машины, предотвращение дублей, расчет напоминаний, таймзону и HMAC-валидацию. Запуск: `npm test`.

### Фаза 2: Движок напоминаний (Reminder Engine) в боте
- **Воркер (`dental_ai_bot/services/reminder_service.py`):**
  - Запускается как фоновая таска `asyncio.create_task` параллельно с ботом.
  - Опрашивает таблицу `reminders` каждую минуту.
  - Отправляет напоминание за **24 часа** и за **2 часа** до визита.
- **Интерактивные инлайн-кнопки:**
  - `✅ Да, приду`: статус ➔ `confirmed`. Сообщение в Telegram редактируется на *"Вы подтвердили визит! Ждем вас в DentaLux."* (исключает повторные нажатия).
  - `🔄 Перенести`: статус ➔ `reschedule_requested`. Администратор получает алерт: *"Пациент просит перенести визит — свяжитесь с ним"*.
  - `❌ Отменить`: статус ➔ `cancelled`. Слот в Mini App мгновенно освобождается, в чат клиники уходит алерт для оперативного заполнения окна.
- **Устойчивость к блокировке бота:**
  - Перехват ошибки `TelegramForbiddenError` (когда пациент заблокировал бота). Статус напоминания помечается как `failed`, а администратору отправляется сообщение: *"Пациент заблокировал бота — позвоните ему лично по телефону +998..."*.

### Фаза 3: Встроенная панель администратора (Admin Panel)
- Доступна прямо внутри Telegram Mini App, не требует установки сторонних приложений.
- **Безопасность (`src/lib/telegramAuth.ts`):**
  - Валидация криптографической HMAC-SHA256 подписи `initData` по токену бота.
  - Проверка Telegram ID пользователя по белому списку `ADMIN_ID`.
- **Компонент `src/components/admin/AdminPanel.tsx`:**
  - **Лента «Сегодня»:** хронологический список визитов текущего дня с цветовыми бейджами статусов и временем до начала.
  - **1-тап действия:**
    - `Подтвердить` (переводит в `confirmed`)
    - `Пришёл` (переводит в `completed`)
    - `Не явился` (переводит в `no_show`)
    - `Отменить` (переводит в `cancelled`)
    - `Позвонить` (нативный вызов `tel:+998...`)
    - `Написать в Telegram` (прямая ссылка `https://t.me/...`)
  - **Календарь на 7 дней:** сетка с подсветкой загруженности по дням недели.
  - **Быстрая ручная запись:** форма для администратора, принимающего звонок по телефону, с мгновенным резервированием слота в системе.
  - **Управление расписанием врачей:** быстрый тумблер рабочих смен врачей на неделю.

### Фаза 4: Аналитический отчёт для владельца клиники
- **Компонент `src/components/admin/OwnerReportTab.tsx`:**
  - Переключатель диапазона: **За 7 дней / За 30 дней**.
  - Ключевые бизнес-метрики:
    - Общее число записей.
    - Доля записей через бота/мини-апп (автоматизация).
    - **Confirmation Rate** (% подтверждений).
    - **No-Show Rate** (% неявок).
    - **Спасенные слоты** (пациенты, вовремя отменившие или перенесшие визит, что позволило принять других людей).
    - **Сэкономленное время персонала** (формула: `подтвержденные_записи * 4 минуты / 60`).
  - **Легковесный SVG-график динамики** (чистый SVG без тяжелых сторонних библиотек вроде Chart.js, идеален для мобильных экранов).
  - **Кнопка «Отправить дайджест в Telegram сейчас»:** формирует сводку и отправляет в чат директора.
- **Команда `/digest` в боте:** выводит сводку за 7 дней по клинике.

### Фаза 7: AI-Guardrails и безопасность диалога
- Модель DeepSeek: строго `deepseek-chat` (официальный API, `api.deepseek.com`).
- **PII Stripping & Regex Masking (`services/ai_service.py`):**
  - Все телефонные номера маскируются регулярным выражением перед отправкой в LLM на `[ТЕЛЕФОН_СКРЫТ]`.
  - Реальные имена пользователей и Telegram ID не передаются внешнему AI.
- **Строгий отказ от выписки лекарств (`data/prompts.py`):**
  - Бот категорически отказывается назначать дозировки антибиотиков, обезболивающих или схему лечения, поясняя, что это опасно для здоровья без очного осмотра, и предлагает записаться на консультацию.
- **Триаж острой боли (Emergency Triage):**
  - При симптомах флюса, травмы зуба, кровотечения или нестерпимой боли бот выдает правила первой помощи (не греть, приложить холод) и предлагает экстренный звонок в клинику.

## 🔌 5. Спецификация API маршрутов Mini App

Все API роуты работают по адресу `https://dentalminiapp.vercel.app/api/...`:

### 1. `GET /api/slots?date=YYYY-MM-DD&doctorId=doctor_id`
- **Ответ:**
  ```json
  {
    "date": "2026-11-05",
    "doctorId": "doc_karimov",
    "slots": [
      { "time": "09:00", "available": true },
      { "time": "09:30", "available": false },
      { "time": "10:00", "available": true }
    ]
  }
  ```

### 2. `POST /api/appointments`
- **Тело запроса:**
  ```json
  {
    "patientName": "Алишер Усманов",
    "patientPhone": "+998901234567",
    "telegramId": 123456789,
    "telegramUsername": "alisher_uz",
    "doctorId": "doc_karimov",
    "serviceId": "damon_q2",
    "date": "2026-11-06",
    "time": "14:00",
    "personalDataConsent": true
  }
  ```
- **Логика:** Проверяет занятость слота. При успехе создает запись в статусе `pending`, планирует напоминания за 24ч и 2ч.

### 3. `PATCH /api/appointments/:id/status`
- **Тело запроса:** `{"status": "confirmed", "reason": "Клиент нажал кнопку Да, приду"}`
- **Логика:** Валидирует переход через `isValidTransition()`, обновляет статус, записывает действие в `AuditLog`.

### 4. `POST /api/appointments/:id/reschedule`
- **Тело запроса:** `{"newDate": "2026-11-07", "newTime": "16:00"}`
- **Логика:** Проверяет доступность нового слота, переносит запись, пересчитывает тайминги напоминаний.

### 5. `GET /api/reports?period=7d` (или `period=30d`)
- **Ответ:**
  ```json
  {
    "period": "7d",
    "totalAppointments": 28,
    "botBookings": 19,
    "confirmedCount": 24,
    "cancelledCount": 2,
    "noShowCount": 2,
    "confirmationRate": 85.7,
    "noShowRate": 7.1,
    "savedSlots": 4,
    "adminHoursSaved": 1.6,
    "dailyBreakdown": [...]
  }
  ```

### 6. `POST /api/demo`
- **Тело запроса:** `{"action": "send_reminder_now" | "create_sample" | "simulate_cancel" | "send_digest" | "reset_seed"}`
- **Логика:** Выполняет симуляцию действий для живой презентации без ожидания реальных таймеров.
